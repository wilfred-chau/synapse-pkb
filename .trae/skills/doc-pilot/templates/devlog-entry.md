# 开发日志条目模板

> 追加到 `docs/progress/dev-log.md` 文件末尾，按时间正序。标题格式与现行日志一致：
> `## YYYY-MM-DD｜主题`。一事一条，写清「背景 / 做了什么 / 关键决策 / 验证 / 遗留」。
> 若 `docs/.doc-pilot.json` 中 `ticket_system.enabled = true`，标题或背景段注明关联票号；
> 未启用工单系统则忽略票号相关字样。

```markdown
## YYYY-MM-DD｜模块或里程碑主题（一句话说明交付物）

**背景**：为什么做这件事（用户需求/上一步遗留/测试暴露）。

**产出**：
- 新增/修改的文件清单（关键文件列出路径）。
- 核心功能点概述。

**过程要点（踩坑与决策）**：
- 关键技术决策及理由（为什么选 A 不选 B）。
- 踩坑记录（若属缺陷修复，详细过程应落在 BUGFIX_LOG，这里只留一句 + 指引「详见 BUG-NNN」）。

**验证**：
- 编译/测试/冒烟命令及结果（如 `npx playwright test` 161 passed）。
- 人工核验要点。

**遗留/Next**：
- 未尽事项、待确认问题、下一步计划。
```

注意：
- 条目内引用其他文档用相对路径（`../xxx/...`）。
- 写完后必须同步刷新 `STATUS.md`（模块表状态、最近动态插入本条摘要、更新日期含隐藏标记）。
- 若启用工单系统（见 SKILL.md「开发前置建票门」），本条应注明关联票号；未启用则跳过此项。
