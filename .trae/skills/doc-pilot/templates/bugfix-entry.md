# BUG 修复记录条目模板

> 追加到 `docs/bugs/BUGFIX_LOG.md`（活跃卷）文件末尾。编号 = 全库现有最大编号 + 1——
> 对 `docs/bugs/` 全目录（含 `history/` 历史卷）搜 `## .*BUG-` 取最大值，历史卷同样计入，
> 编号全局连续、永不重置。日期用实际修复日期。保持与历史条目完全一致的结构，便于 AI 按标题行跳读检索。

```markdown
## [YYYY-MM-DD] BUG-NNN: 一句话标题（模块 + 现象 + 根因关键词）

**现象**
1. 用户可见的异常表现（附报错码/接口/复现路径）。
2. ...

**根因**
1. 精确到文件与行的原因分析，区分前端/后端/数据/配置。
2. ...

**修复**
- `文件路径`: 改了什么、为什么这样改。
- 数据库/SQL 有动则单列（含幂等性处理）。

**验证**
- 编译/构建/测试命令及结果；需重启/强刷/数据修复的显式写出。
- 浏览器人工验证要点（按步骤列出，供回归）。

**经验教训**
- 可复用的方法论或坑位提示（这条是全日志最有价值的部分，认真写）。
```

注意：
- 若为历史 BUG 复发，标题后注明「复发于 BUG-XXX」，并在经验教训中分析为何复发。
- 涉及数据修复的必须写「数据修复」小节。
